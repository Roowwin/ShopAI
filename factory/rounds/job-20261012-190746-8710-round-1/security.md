# Security review round 1 - job-20261012-190746-8710 (nested Shop sub-menu): security lens clean, CHANGES for a build-breaking duplicate import

- URL safety is sound: `shortcutHref` feeds only `new URLSearchParams({ category: categoryName.toLowerCase(), q: term })` and returns a literal-prefixed `"/?" + p.toString()` (navMenu.ts:44-45). `URLSearchParams` form-encodes every byte outside `A-Za-z0-9*-._` (space -> `+`), so a hostile category name cannot emit `&`/`#`/`?` to close the query, cannot become a scheme or authority, and the `/?` prefix is a literal — the result is always a same-origin path. `catLink`'s `"/category/" + encodeURIComponent(c.name)` (Header.tsx:18) encodes `/ ? : #`, the same construction as baseline job 20.
- Nothing becomes markup, and the aria-label concatenation holds: every label is a JSX text child (`{l.label}` NavDropdown.tsx:269, `{c.label}` NavDropdown.tsx:315, `{s.label}` Header.tsx:162) so a name renders as text and is never re-parsed; the aria-labels are plain string props (`"Show " + l.label + " sub-categories"` NavDropdown.tsx:278; `(isOpen ? "Hide " : "Show ") + c.name + " sub-categories"` Header.tsx:146) set through React's DOM attribute API, so a `"` in a category name is escaped and cannot break out of the attribute; no `dangerouslySetInnerHTML`/`innerHTML`/`eval` appears in the diff.
- No new data path and no auth surface: the added lines contain no fetch, endpoint, parameter name, cookie, token or storage access (whole-diff grep for `fetch|cookie|token|secret|password|process.env|localStorage|dangerouslySetInnerHTML|eval(|javascript:` matches only the two `import` lines, Header.tsx:8-9); the sub-level is static literal data (navMenu.ts:24-36); the child links reuse Job A's existing `category` + `q`; only the 3 allowed files changed (no package.json/lockfile, no backend), and the pre-existing `/store/categories` GET and `cartGet()` are untouched.
- Finding (low, introduced here): `NAV_SHORTCUTS[c.name]` is an inherited-key read on an object literal (Header.tsx:19 and Header.tsx:137), so a category named `constructor`, `toString` or `__proto__` resolves to a truthy non-array and the following `sub.map(...)` (Header.tsx:22, Header.tsx:159) throws, crashing the header render. Reachable only via an admin-created category behind the public read-only `/store/categories`, so low severity, not anonymous-reachable; use `Object.hasOwn(...)`/a `Map` to close it.
